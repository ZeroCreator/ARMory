# ARMory MCP для Codex и других клиентов

ARMory предоставляет Kanban-инструменты по протоколу MCP. В репозитории ARMory Codex запускает локальный stdio-сервер из проектной конфигурации. HTTP endpoint остаётся доступен другим MCP-клиентам.

Например, в проекте с подключённым MCP можно попросить Codex создать задачу в ARMory, получить её номер, а позднее сказать «возьми задачу #N в работу». Codex загрузит её через MCP и продолжит работу с файлами текущего проекта.

## Возможности

- `list_projects` — найти проекты ARMory по названию.
- `list_task_statuses` — получить колонки проекта.
- `list_tasks` — получить список задач проекта.
- `create_task` — создать задачу, выбрав проект по имени или ID; по умолчанию используется первая колонка проекта.
- `get_task` — получить задачу по глобальному номеру, без ID проекта.
- `take_task_into_work` — перевести задачу в распознанную колонку «В работе» и назначить AI-исполнителя.
- `update_task` — изменить выбранные поля задачи.
- `complete_task` — переместить задачу в финальную колонку и записать результат. Инструмент не архивирует задачу и не меняет `is_closed`.

Если название проекта неоднозначно, MCP вернёт подходящие проекты, чтобы Codex уточнил выбор. Если в проекте не удаётся определить колонку «В работе», MCP вернёт доступные колонки, а не выберет статус наугад.

## Настройка ARMory

1. Задай `MCP_API_KEY` в окружении сервера ARMory. Сгенерируй отдельный случайный ключ и передавай его клиентам безопасным способом.
2. Для публичного режима добавь `/mcp` в список маршрутов, которые пропускает auth gateway без браузовой сессии. Проверку ключа выполняет само MCP-приложение:

```yaml
- OAUTH2_PROXY_SKIP_AUTH_ROUTES=/wopi/.*,/mcp/?
```

3. Перезапусти ARMory. Streamable HTTP endpoint доступен по адресу `https://<your-domain>/mcp`.

Без `MCP_API_KEY` endpoint возвращает `503`; неверный или отсутствующий ключ — `401`.

## Подключение Codex в папке ARMory

В репозитории уже есть `.codex/config.toml`: он запускает `scripts/armory-mcp.sh` только для проекта ARMory. Скрипт читает `MCP_API_KEY` и `ARMORY_BASE_URL` из локального `.env` приложения. Ключ не нужно копировать в конфигурацию Codex.

```toml
[mcp_servers.armory]
command = "scripts/armory-mcp.sh"
default_tools_approval_mode = "writes"
```

Открой папку репозитория ARMory в Codex и перезапусти сессию после изменения конфигурации. Проектную `.codex/config.toml` Codex загружает только для доверенных проектов. Проверь подключение:

```bash
codex mcp list
```

В открытой сессии команда `/mcp` должна показать сервер `armory` и его инструменты.

Для работы с ARMory из другого репозитория MCP-сервер подключается в `.codex/config.toml` того проекта отдельно. HTTP-конфигурация выглядит так:

```toml
[mcp_servers.armory]
url = "https://<your-domain>/mcp"
bearer_token_env_var = "ARMORY_MCP_TOKEN"
default_tools_approval_mode = "writes"
```

Задай `ARMORY_MCP_TOKEN` в окружении до запуска Codex. В URL не добавляй завершающий слэш.

## Работа с задачами

Когда Codex открыт в папке с подключённым MCP, можно попросить его:

```text
Создай в ARMory задачу в проекте «<название проекта в ARMory>»:
<кратко опиши задачу>
```

Codex найдёт проект через `list_projects`, создаст задачу и ответит её номером и ссылкой, например `Задача #<номер>: <ссылка>`.

Чтобы начать работу, в этом же чате напиши:

```text
Возьми задачу #<номер> в работу.
```

Codex загрузит задачу по номеру, переместит её в колонку «В работе» и продолжит работу с файлами открытого проекта. Номер задачи глобальный в ARMory, поэтому указывать `project_id` для получения задачи не нужно.

Если Codex не находит сервер `armory` в `/mcp`, проверь `codex mcp list`, доверие к проекту и перезапусти сессию. Для локального stdio-подключения проверь `.env` с `MCP_API_KEY` и `ARMORY_BASE_URL`; для HTTP-подключения — наличие `ARMORY_MCP_TOKEN` в окружении процесса Codex.

Номер задачи глобальный в пределах ARMory, поэтому `project_id` не нужен при получении или взятии задачи в работу.

## Безопасность и совместимость

- HTTP MCP endpoint требует bearer-токен или заголовок `X-MCP-API-Key`.
- Для внутренних вызовов API ключ принимается только на маршрутах чтения проектов, статусов и задач, создания и обновления задач, а также регистрации настроенного MCP-исполнителя.
- Храни ключи в окружении или менеджере секретов; не коммить конфигурацию MCP с секретами.
- Для Streamable HTTP указывай URL без завершающего слэша, чтобы избежать перенаправления `/mcp/` на `/mcp`.
