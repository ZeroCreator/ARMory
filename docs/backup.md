# Бэкапы и синхронизация

Все данные ARMory хранятся в двух местах:
- `data/armory.db` — база данных SQLite
- `data/uploads/` — загруженные файлы

## Ручной бэкап

```bash
cd <project-directory>
tar -czvf backup_$(date +%Y%m%d_%H%M%S).tar.gz data/armory.db data/uploads/
```

Получится архив вида `backup_<timestamp>.tar.gz`.

## Восстановление из бэкапа

```bash
cd <project-directory>
tar -xzvf backup_<timestamp>.tar.gz
```

## Синхронизация с Яндекс.Диском

В интерфейсе операции доступны на отдельной странице **Инструменты → Синхронизация** (`/synchronization`). Блоки «Статистика», «Синхронизация с Яндекс.Диском» и «Alexandrite» можно сворачивать / разворачивать; состояние сохраняется в браузере.

### Статистика

Карточки с информацией о локальных данных (проекты, разделы, группы, файлы, заметки и т.д.) и статусе подключения к Яндекс.Диску.

### Синхронизация с Яндекс.Диском

#### Сохранить на Яндекс.Диск
Загружает `armory.db` и все файлы из `data/uploads/` на Яндекс.Диск в папку `YANDEX_DISK_PATH` (по умолчанию `ARMory/data/`). Файлы, уже имеющиеся на диске, пропускаются. Операция выполняется в фоне; интерфейс показывает прогресс по `job_id`.

#### Загрузить с Яндекс.Диска
Скачивает `armory.db` и папку `uploads/` с Яндекс.Диска и восстанавливает локально. Перед операцией автоматически создаётся локальная резервная копия в `data/backups/auto_<timestamp>/`. Выполняется синхронно.

### Архивные бэкапы ARMory

Отдельный функционал создаёт снапшоты в виде `.tar.gz`. В форме **Куда сохранить бэкап?** доступны три варианта:

- **Только локально** — архив сохраняется в `data/backups/` рядом с данными приложения.
- **Только на Яндекс.Диск** — архив сохраняется в папку `YANDEX_DISK_BACKUPS_PATH` (по умолчанию `ARMory/backups/`), временный локальный файл после загрузки удаляется.
- **Локально и на Яндекс.Диск** — один архив сохраняется в обоих местах.

Каждый архив содержит `armory.db` и `data/uploads/`. В интерфейсе архивы разделены на два самостоятельных окна: **Локальные копии** и **Копии на Яндекс.Диске**. В каждом окне отображаются размер и дата архива, а также доступны действия **Скачать**, **Восстановить** и **Удалить**. Восстановление всегда изменяет локальные данные; перед ним приложение создаёт автоматическую локальную копию в `data/backups/auto_<timestamp>/`.

Архивы не зависят от прямой синхронизации. Прямая синхронизация и архивный бэкап — разные операции: первая обновляет отдельные объекты `armory.db` и `uploads/` на Яндекс.Диске, второй создаёт версионируемый файл для хранения и скачивания.

### Оценка restic

[restic](https://github.com/restic/restic) целесообразен как следующий этап, если нужны шифрование, дедупликация, инкрементальные снапшоты, проверка целостности и политика хранения версий. Он поддерживает локальное хранилище и удалённые бэкенды, а доступ к Яндекс.Диску можно организовать через [rclone-бэкенд](https://restic.readthedocs.io/en/stable/030_preparing_a_new_repo.html#other-services-via-rclone); [rclone поддерживает Яндекс.Диск](https://rclone.org/yandex/).

Для текущего ручного сценария с кнопками **Создать бэкап** и **Скачать** переход на restic не требуется: обычный архив проще восстановить и передать пользователю. Интеграция restic добавит отдельный бинарный компонент, пароль репозитория, настройку rclone и необходимость встроить работу со снапшотами и политиками `forget`/`prune` в интерфейс. Перед возможной интеграцией нужно отдельно обеспечить согласованный снимок SQLite, чтобы резервная копия не создавалась во время записи базы.

### Alexandrite

Папка `ALEXANDRITE_VAULT_PATH` (по умолчанию `data/alexandrite`) синхронизируется с Яндекс.Диском отдельно от основных данных ARMory:

- **Сохранить на Яндекс.Диск** — фоновая загрузка папки Alexandrite с отображением прогресса (`job_id`).
- **Загрузить с Яндекс.Диска** — замена локальной папки Alexandrite версией с диска. Перед операцией создаётся локальная резервная копия.
- **Архивные бэкапы** — создание архива `alexandrite_backup_<timestamp>.tar.gz` только с содержимым папки Alexandrite, восстановление и удаление архивов.

## Настройка

Добавьте в `.env`:

```env
YANDEX_DISK_TOKEN=<yandex-oauth-token>
YANDEX_DISK_PATH=ARMory/data
YANDEX_DISK_BACKUPS_PATH=ARMory/backups
YANDEX_DISK_ALEXANDRITE_PATH=ARMory/alexandrite
ALEXANDRITE_YANDEX_ROOT_PATH=
TIMEZONE=Europe/Moscow
```

## Автоматический бэкап (cron)

```bash
# Каждый день в 3:00 утра
crontab -e
<cron-schedule> cd <project-directory> && tar -czf <backup-directory>/app_$(date +\%Y\%m\%d).tar.gz data/armory.db data/uploads/ >/dev/null 2>&1
```

## Бэкап при деплое на другой сервер

```bash
# На исходной машине. Секреты из .env перенеси отдельно через защищённый канал.
tar -czvf backup_$(date +%Y%m%d_%H%M%S).tar.gz data/armory.db data/uploads/

# На новом сервере
mkdir -p <project-directory> && cd <project-directory>
tar -xzvf backup_<timestamp>.tar.gz
# Запуск после настройки переменных окружения
docker compose up -d --build
```
